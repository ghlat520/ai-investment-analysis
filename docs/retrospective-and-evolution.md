### 2.2 关键洞察

**问题发现的4种模式**（可转化为自动检测）：

```
1. 异常值对比    → 自动化: 数值超过阈值触发告警
   案例: 002160估值-95分 → 发现PE负值污染

2. 多次运行取方差 → 自动化: 每次分析后存评分，跨次比较
   案例: 300054 moat 极差44分 → 缺乏量化锚点

3. 端到端验证    → 自动化: 输入预期值，与实际输出比较
   案例: 目标价3.19元 vs 预期39元 → LLM忽略代码值

4. 领域知识判断  → 无法自动化（需要人）
   案例: 鼎龙6条产品线增速不同 → 需要分业务估值
```

**修复的可靠性层次**：

```
确定性100% ──── 代码规则（D1-D6）
                代码覆写（M2: YAML目标价覆写LLM）
                基础设施（I1: Semaphore）
减少方差95% ─── 量化锚点（M1: moat评分锚定）
需要人判断 ──── 架构升级（M3: 分业务前瞻估值）
```

**最重要的教训：代码 > LLM**

| 维度 | 代码计算 | LLM判断 |
|------|---------|---------|
| 目标价 | YAML精确算（39/65/138元）| 3.19元（错了2个数量级）|
| PE百分位 | 代码排序（确定性）| 可能漏算负值 |
| ROE年化 | Q1×4/Q2×2/Q3×4÷3（公式）| 不知道要年化 |
| 增速假设合理性 | 无法代码化 | LLM擅长（"50%增速是否现实？"）|
| 竞争格局 | 无法代码化 | LLM擅长（"护城河来自专利/客户粘性"）|

**结论**：可计算的交给代码，不可计算的交给LLM，绝不混用。

## 六、第一性原理：智能体自进化架构

### 6.1 本质问题

> **如何让系统在没有人干预的情况下，发现自身输出的问题并修正？**

### 6.2 约束分析

| 约束 | 不可突破？ | 说明 |
|------|----------|------|
| LLM输出有随机性 | **是** | temperature>0，同一输入不同输出 |
| 代码计算是确定性的 | **是** | 同一输入必然相同输出 |
| 自动改代码有引入bug风险 | **是** | 必须有人审批 |
| 验证成本高（11min/次） | **是** | 不能无限重跑验证 |
| 数据质量规则可穷举 | **否** | 新数据源=新问题，但可逐步积累 |

### 6.3 五层自治金字塔

```
                    ┌─────────────┐
                    │   L5 架构   │ ← 需要人设计
                    │   演进      │   新增Agent / 改交互模式
                    ├─────────────┤
                    │  L4 Prompt  │ ← 需要人审批
                    │  自优化     │   A/B测试 prompt 变体
                    ├─────────────┤
                    │ L3 跨股票   │ ← 半自动
                    │ 模式学习    │   识别行业特征 / 积累案例
                    ├─────────────┤
                    │ L2 输出     │ ← 全自动（只报警）
                    │ 一致性      │   偏差检测 / 稳定性监控
                    ├─────────────┤
                    │ L1 数据     │ ← 全自动（自动修正）
                    │ 免疫系统    │   D1-D6 / 异常值检测
                    └─────────────┘
```

```
3. 人看两版输出，决定是否升级

关键约束：
- 必须人审批（prompt改错可能导致所有分析变差）
- 每次只改一个Agent的prompt（可控范围）
- 保留旧版本用于回滚
```

**L5 架构演进（需人设计）** — 🏗️ 长期

```
可能的演进方向：
1. 新增Agent: ESG评分、量化因子回测、管理层质量评估
2. 交互模式: Agent间互相"复审"（如估值Agent参考基本面Agent的ROE数据）
3. 多模型: 关键决策用Claude API交叉验证Ollama结果
4. 时序: 每周/月自动重新分析已持有股票，监控趋势变化
```

### 6.4 反馈闭环设计

```
┌──────────────────────────────────────────────────────────────────┐
│                        自进化反馈闭环                             │
│                                                                  │
│  ① 分析执行                                                      │
│     └→ 采集数据 → 9-Agent并行分析 → 融合决策 → 报告生成           │
│                                                                  │
│  ② 质检报告（L1+L2 自动）                                        │
│     └→ 数据层检查 → 输出一致性检查 → 生成质检报告                  │
│                                                                  │
│  ③ 异常分类                                                      │
│     ├→ 已知类型（D1-D6/I1）→ 检查规则是否已覆盖                   │
│     │   ├→ 已覆盖 → 记录"规则已生效"                              │
│     │   └→ 未覆盖 → 自动添加规则（L1）                            │
│     └→ 未知类型 → 标记"需人工review"                              │
│                                                                  │
│  ④ 修复验证                                                      │
│     └→ 重跑该股票 → 确认评分变化在预期范围                         │
│                                                                  │
│  ⑤ 知识沉淀                                                      │
│     └→ 写入规则库 → 后续所有分析自动应用                           │
│                                                                  │
│  ⑥ 下次分析自动受益 ──────────────────────→ 回到 ①               │
└──────────────────────────────────────────────────────────────────┘
```

### 6.5 风险控制铁律

```
1. 代码 > LLM          — 可精确计算的绝不用LLM猜
2. 报警 > 自动修       — 不确定的只报警，不自动改
3. 可回滚 > 不可逆     — 每次修改保留前一版本
4. 局部 > 全局         — 新规则先对单股验证，确认后推广
5. 串行 > 并行         — Ollama约束下不要贪快
6. 免疫规则只加不减    — D1-D6是系统的"抗体"，不能删除
```

## 八、从"训练模型"到"自进化系统"的本质区别

### 为什么不用ML训练？

| 维度 | ML训练 | 规则+反馈系统 | 我们的选择 |
|------|--------|-------------|-----------|
| 学习方式 | 大量数据训练参数 | 规则积累+案例库 | **规则** |
| 需要数据量 | 数千~数万 | 几十个case即可 | 当前<50个 |
| 可解释性 | 黑箱 | 每条规则可追溯 | **必须可解释** |
| 分布漂移 | 历史≠未来 | 规则可随时更新 | 市场每年变 |
| 验证成本 | 需要holdout set | 对比前后即可 | 11min/次 |

### 正确路径：免疫系统 + 反馈闭环

```
每次分析积累一条"经验"
  ├─ 确定性经验 → 自动变成代码规则（D1-D6）
  ├─ 统计性经验 → 量化锚点+方差约束（M1）
  ├─ 架构性经验 → 人审批后实施（M3）
  └─ 所有经验 → 写入Memory/文档，不丢失

50只股票后 → 统计模式浮现（行业PE分布/Agent稳定性排名）
100只股票后 → 评分vs实际涨跌回测（验证系统预测能力）
200只股票后 → 自动行业校准（军工PE阈值/消费股ROE基准）
```

### 终极目标：三级自治

```
Level 1 — 自动守护: 每次分析自动执行D1-D6规则，零人工
Level 2 — 自动报警: 输出异常自动标记，人只看异常case
Level 3 — 自动校准: 积累足够数据后，行业基准自动更新（需人确认）
```

> **核心理念：不是让Agent改自己的代码，而是建立"免疫系统"——已知问题自动修正，未知问题只报警不瞎改。系统越跑越健壮，但每一步都可解释、可回滚、可控。**
