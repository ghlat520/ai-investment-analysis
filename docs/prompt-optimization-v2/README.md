# 提示词优化方案 v2

## 对比分析：现有系统 vs 参考提示词

### 现有系统的优势（保留）
| 能力 | 说明 |
|------|------|
| 多Agent并行 | 9维度DAG并行，远优于单Agent线性流 |
| Code+LLM Hybrid | 量化基础分+LLM定性微调，比纯LLM可靠 |
| 信号标准化 | -100~+100统一评分协议 |
| 多源fallback | 5+数据源auto-fallback，熔断降级 |
| 市场自适应 | 牛/熊/震荡动态权重 |
| 多空辩论 | bull vs bear对等辩论机制 |
| 护城河框架 | Morningstar五维评估 |

### 参考提示词的亮点（借鉴）
| 能力 | 参考提示词有 | 现有系统缺 | 优化方案 |
|------|------------|-----------|---------|
| 收入构成拆解 | 各业务板块营收/利润/增速预测 | 仅笼统的营收增速 | fundamental.md新增收入构成分析框架 |
| 估值模型选择逻辑 | 论证为什么选PEG/DCF | 直接用PE/PB分位 | valuation.md新增模型选择决策树 |
| 完整计算过程 | 公式+数字代入+结果 | 仅给分数无推导 | valuation.md强制计算过程透明 |
| 因子权重表 | 因子-权重-数据来源表格 | 权重在config中但报告不展示 | fusion.md/report.md展示权重表 |
| 情景分析表 | 保守/中性/乐观含触发条件和概率 | 简单的三档目标价 | valuation.md新增完整情景分析框架 |
| 风险交叉验证 | 对风险项深度搜索验证 | 简单汇总各Agent风险 | fusion.md新增风险交叉验证矩阵 |
| 操作策略具体化 | 建仓/加仓/止盈/止损具体价位 | 仅给百分比 | fusion.md新增完整操作策略框架 |
| 数据源溯源 | 每个数据点标注来源 | 无溯源 | 全链路新增[来源]标注要求 |

### 参考提示词的问题（不借鉴）
| 问题 | 原因 |
|------|------|
| 单Agent线性 | 架构落后，保持我们的多Agent并行 |
| 依赖第三方插件 | 不可控，保持我们的本地数据源 |
| 无量化评分 | 主观，保持我们的-100~+100标准化 |
| 无置信度机制 | 无法判断可靠性，保持我们的confidence |
| 冗长重复 | token浪费，我们的提示词精简且结构化 |

## 优化文件清单

| 文件 | 用途 | 主要改进 |
|------|------|---------|
| `master.md` | 系统编排提示词 | 新增：流程规范、信号协议、质量标准 |
| `valuation.md` | 估值分析Agent | 重写：模型选择决策树、计算过程规范、情景分析表 |
| `fundamental.md` | 基本面Agent | 重写：收入构成框架、红旗/绿旗清单、现金流交叉验证 |
| `fusion.md` | 决策融合Agent | 重写：风险交叉验证、操作策略框架、数据溯源 |
| `report.md` | 报告生成Agent | 重写：双格式输出、完整报告结构模板、表格优先 |

## 核心设计原则（第一性原理）

投资分析的本质需求 → 提示词设计目标：

```
数据准确 → 多源交叉验证 + [来源]标注 + 数据完整度评分
逻辑严谨 → 量化基础 + 计算过程透明 + 红旗/绿旗检测
可操作   → 具体价位(精确到分) + 仓位比例 + 触发条件
风险可控 → 交叉验证矩阵 + 否决权机制 + 条件止损
可溯源   → 结论→Agent→数据源 全链路追踪
```
